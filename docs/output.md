# 다산순환로 20 출력 검증

제공된 편집용 SVG에서 좌표, 글자 배치, 색과 선 두께를 추출한 MapSpec을 Chrome에서 출력했다. 기준 주소는 **경기도 남양주시 다산순환로 20**이다. 이 검사는 렌더러와 파일 구성에 적용한다. 다산중앙로82번안길 74의 위치 검수는 별도 기록을 따른다.

## 재현

프로젝트 루트에서 `npm ci` 후 `node tests/export-browser.mjs artifacts`를 실행한다. macOS에서는 설치된 Google Chrome을 찾는다. 다른 환경에서는 실행 가능한 Chromium의 경로를 `CHROME_PATH`에 지정한다. 테스트는 로컬 루프백에서 Vite를 잠시 실행하고 완료 후 종료한다. v2 원본이 있으면 환경변수 `WEDDING_V2_ARCHIVE`에 그 ZIP 경로를 지정한다. 이때 추가로 v2의 samples/full 투명 PNG와 대조한다. 브라우저·운영체제 또는 라이브러리를 변경하면 픽셀과 해시가 달라질 수 있다.

- 로컬 기준 결과 ZIP은 `artifacts/Dasan20_Files.zip`에 생성된다.
- 로컬 파일별 해시와 실행 기록은 `artifacts/export-check.json`에 기록된다.
- [브라우저 회귀 검사](../tests/export-browser.mjs)

실행 기록의 durationMs는 글꼴을 읽고 2회 출력·미리보기·비교·취소 검사를 모두 수행한 시간이다. 개별 생성 시간, 아이폰 메모리 사용량, 실제 기기의 다운로드·재열기는 별도로 측정해야 한다.

## 구현

앱의 제한된 도형 모델에서 만든 두 개의 SVG를 출력기에 전달한다. Noto 글리프를 로컬에서 윤곽선으로 변환해 PNG와 PDF에서 시스템 글꼴 대체를 피한다. 브라우저 Canvas가 PNG를 한 번에 하나씩 만들고 각 파일의 인코딩 직후 비트맵 버퍼와 임시 URL을 해제한다. PNG 밀도 청크는 CRC까지 다시 계산한다. 벡터 PDF는 svg2pdf.js와 jsPDF로 도형을 그리며, ZIP에는 완성 파일과 안내·검수 문서만 넣는다. PDF와 ZIP의 내부 날짜는 재현성을 위해 고정하고 실제 검수일은 별도 검수 문서에 기록한다.

## 다산중앙로82번안길 74

[다산74 원천 기록](../data/dasan74.json)의 단지 대표점, 도로 및 시설을 앱의 배치 엔진으로 처리해 재편집 프로젝트 `artifacts/Dasan74_Project.json`과 인쇄·공유용 `artifacts/Dasan74_Files.zip`을 만들었다. JSON 가져오기 후 배치가 보존되는지, 위치 검수가 확인 필요 상태인지, ZIP의 10개 파일 해시가 일치하는지, 전체·지도 전용 벡터의 OSM 출처 표기가 유지되는지 검사했다. 출력에서 도로명은 해당 도로의 방향으로 회전한다. 목적지·도로명·시설명의 예상 글자 영역과 그려진 도로선 사이의 교차를 회귀 검사하고 PDF를 육안으로 대조했다. 실제 보행·차량 입구와 독립적인 현장 대조는 남아 있다.

글자 윤곽선 경로 문자열은 전체 또는 지도 전용 한 장당 8 MiB까지 허용한다. 가져온 프로젝트에서 같은 긴 문구를 반복하여 브라우저 메모리를 소진하는 경우를 줄이기 위한 초기 상한이다. 초과 시 해당 파일 생성을 중단하고 문구를 줄이라는 안내를 표시한다.

## v2 기준 파일과의 비교

동일한 다산20 시안에서 v2 미검수 제목 **원본 재현 · 위치 재확인 전**을 24 단위, 자간 0으로 출력했다. 2026년 11월 20일 생성본과 v2 `samples/full`의 전경 픽셀 교집합/합집합은 PNG 96.63%, PDF 99.78%였다. PDF는 Poppler에서 681 × 700 px로 렌더한 뒤 명도 220 미만의 픽셀을 비교했다. 제공된 `reference/Dasan20_Wedding_Map_Files`는 제목이 **오시는 길**이며, 같은 방법의 대조 결과는 PNG 93.05%, PDF 96.09%였다. 두 기준 모두 위치 대조 일자를 승계해 독립 검수로 표시하지 않았다.
