# 오시는 길

도로명주소와 OpenStreetMap 도로 자료로 청첩장 약도를 만들고, 글자·표식을 편집해 인쇄 파일을 받는 한국어 웹앱이다. 브라우저에서 실행하며 프로젝트와 완성 파일은 같은 기기와 브라우저 프로필의 IndexedDB에 보관한다.

[작업실 열기](https://invitation-map-studio.github.io/)

1. 전달받은 전용 이용 암호로 작업실을 연다. 처음에는 다산중앙로82번안길 74의 보관본이 열린다. 꽃은 단지 중심이다.
2. 새 작업은 ‘주소로 약도 만들기’를 누른다. 공개 OSM 한국 추출본의 도로명·건물번호 색인에서 후보를 찾는다. 해당 도로명에 필요한 조각 한 개만 불러온다. 색인에 없는 주소는 실시간 조회를 시도한다. 후보의 이름·좌표·객체를 확인해 선택한다. OSM 주소가 누락된 곳은 자동 생성이 제한된다. 다산20은 ‘기준 약도 보기’에서 열 수 있다. 평가한 공공 장소 9곳은 조사한 시설 후보를 선택하면 온라인 갱신 실패 시에도 보관된 지리 자료로 제작할 수 있다.
3. 지도에서 글자와 표식을 선택해 이동하거나 편집창에서 좌표·문구·표시 상태·먹색을 수정한다. 150 dpi 미리보기로 실제 출력 글꼴을 확인한다. 작업 전 상태로 돌아가려면 ‘실행 취소’를 누른다.
4. ‘인쇄 파일 만들기’를 누르면 600 dpi PNG 4개, 벡터 PDF, SVG 3개, 사용 안내와 검수 기록을 내려받을 수 있다. ZIP은 10개를 모두 담는다. 기기에 보관한 ZIP은 과거 버전 그대로 다시 받을 수 있다.
5. 기기를 바꾸기 전에 ‘JSON 백업’과 ZIP을 모두 받는다. JSON을 가져오면 배치를 재편집할 수 있으며, 위치 대조와 데이터 최신성은 다시 확인한다. ‘기기 데이터 삭제’로 저장한 지도와 파일을 지울 수 있다.

## 실행과 배포

Node 22에서 `npm ci`, `npm run dev`를 실행한다. 로컬호스트에서 운영 검증값이 없으면 최초 사용자가 그 브라우저의 전용 암호를 설정한다. `npm test`는 시간 경계·오류 처리·배치 회귀를, `npm run build`는 타입과 정적 빌드를 검사한다. 설치된 Chrome으로 `node tests/export-browser.mjs artifacts`를 실행하면 출력 파일을 실제로 생성한다.

공개 배포는 GitHub Pages의 Actions 모드를 사용한다. `npm run lock:setup`에서 새 전용 암호를 숨김 입력하고 결과의 등호 오른쪽 검증값을 저장소 Actions 변수 `WEDDING_LOCK_VERIFIER`로 등록한다. main에 소스를 반영하거나 Pages 워크플로를 수동 실행한다. 앱의 securityMode는 `pages-only`이고 새로고침하면 잠긴다. 검증값 변경 후 재배포하면 새로 연 탭에 적용된다. 암호와 검증 로직은 지인용 화면 잠금이며 API 강제 인증을 제공하지 않는다.

배포 장애 시 마지막 정상 커밋을 복원해 워크플로를 재실행한다. 긴급 중지는 Pages 설정에서 사이트 게시를 해제한다. 선택한 공급자의 실제 키가 있는 경우 공급자 콘솔에서 API와 키도 중지하고 원인을 확인한 뒤 교체한다. GitHub Pages는 기존 탭이나 이미 내려받은 파일을 회수할 수 없다.

## 데이터와 검수

OSM 자료는 마지막 성공 조회부터 24시간 동안 재사용한다. 수동 갱신 또는 만료 후 새 요청에서만 다시 조회한다. 이전 성공 시각, 최근 사용 시각, 위치 대조 시각은 별도로 보존한다. 공식 단지 주소 확인, 도로 모양 변환, 파일 출력, 실제 입구 대조의 결과는 각각 기록한다. 실패하면 마지막 성공본으로 로컬 편집·출력을 계속할 수 있다.

운영 배포에서 네이버 유료 API와 Juso 승인키는 사용하지 않는다. 네이버 연동을 활성화하기 전에는 신청, 등록 도메인, API별 강제 차단과 키 교체를 시험해야 한다. 실제 위치 정보만 있는 장소에서는 임의의 입구나 주차 동선을 생성하지 않는다.
